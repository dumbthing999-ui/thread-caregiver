# Day 3 audit for the Day 4 specification

Independent local code/document review on September 13, 2026. Prior Day 3 files were not edited. This audit ran the existing verifier and small synthetic in-memory probes; it used no network, live model, real patient inputs or external actions. Findings concern local prototypes, not a deployed service.

## Verified baseline and narrowed verdict

`PYTHONDONTWRITEBYTECODE=1 python3 docs/day03/verify_pack.py` returned PASS: 17 required files, 9 valid local links, and 13 tests with zero failures (this run: 0.003 seconds). This verifies those assertions, not all Day 1 obligations. No actual productive agent-hour total is inferred.

- A demonstrates exact substring resolution on the supplied UTF-8 fixtures, repeated-substring disambiguation, and rejection of the tested binary marker. Narrow to that text prototype; PDF provenance is not demonstrated.
- B demonstrates selected quote-presence and enum/keyword rejection cases. The general publication gate is **not accepted**: altered values, empty evidence and disguised clinical tasks pass.
- C demonstrates a sequential in-memory replacement path and one identical acknowledgement retry. Atomic concurrency, authorization, persistent immutable history, scoped dependencies and rehearsal are **not accepted**.

Day 4 may specify the missing controls and executable acceptance obligations. Preserve the historical 13/13 result while superseding broad feasibility claims; no public/shared-write implementation is validated by it.

## Reporting and verifier discrepancies

- [research-spikes.md](../day03/research-spikes.md):29–30 gives appointment offsets `[142:159]` and `[183:198]`. Resolving the current fixture strings prints `[129:146]` and `[157:172]`; the reported numerical table does not match current artifacts.
- [review.md](../day03/review.md):26 presents caregiver frustration as a finding. There is no participant evidence in these spikes. It remains a hypothesis, as does the superiority of selective invalidation.
- review.md:11,47 and research-spikes.md:8,64,91 overstate fine-grained invalidation, unconditional nonclinical blocking, immutable persistence and atomic concurrency. The counterexamples above narrow those claims.
- [verify_pack.py](../day03/verify_pack.py):87–106 checks stored counts against hardcoded 13/0; it does not reconcile all status metrics with execution. Its header promises FR/INV tracing, but `verify_all` at 131–166 calls only file/link/status/spike checks. Misnumbered traces are therefore undetected: C:7–14 reverses FR-05/FR-06 meanings and maps history to FR-10; the actual [Day 1 contract](../day01/scope-and-acceptance.md) gives FR-10 to simulation/offline/replay disclosure, INV-06 to historical completion, and INV-07 to stale writes/idempotency.
- The 13 tests contain no real authenticated two-context service, durable database, PDF rendering, rehearsal implementation or multi-source conflict evaluation. Fixture presence is not executed acceptance coverage.

## Probe reproducibility

All probes imported existing modules with `PYTHONDONTWRITEBYTECODE=1`; no prior source edits were required. Construct the document with `SourceDocument.from_file` on `s01_v1.txt`. Feed `DeterministicTaskGate.validate_and_filter` an instruction with a mismatched value/existing quote, or empty fields, linked to an allowed CALL_OFFICE task. Inspect accepted lists and `is_blocked`. Service probes instantiate a fresh `AuthoritativeCoordinationService`, register r1, and call the public methods with the actors/keys described above. The anchor-identity probe uses `dataclasses.replace` to preserve the document ID while changing content/digest. The history probe directly mutates an event payload.

For the deterministic interleaving, install a Python trace callback that checks `frame.f_code.co_name == 'complete_task'`, `event == 'line'`, and `frame.f_lineno == 260`; disable tracing inside the callback, then call `register_revision('r2', 'd2', 2, 'r1')`. Complete the original r1 task and inspect revision state, task state and final event revision. This schedules a competing operation at the known check/write boundary without changing the implementation. A Day 4 regression suite should preserve these as explicit known failures against the historical spike, while future implementations must reject them.
